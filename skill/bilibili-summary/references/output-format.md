# biliex 内容包结构

`& "<BILIEX>\biliex.cmd" fetch <目标> --out <目录>` 的产物布局（默认 `<目录>` 为 `./out`）：

```
out/<bvid>/
  index.md             入口文件：元数据 + 命中级别 + 官方摘要 + 分块清单 + 总结要求
  meta.json            结构化元数据与各级命中情况（给程序读）
  p<N>-transcript.md   分 P 完整转录，每行 `[MM:SS] 文本`
  p<N>-chunks/C##.md   分块文件，块头注释含时间范围，块间有重叠
  raw/                 上游原始 JSON（证据留档，争议时可回查）
    view.json
    p<N>-player.json
    p<N>-conclusion.json
    p<N>-playurl.json  仅 L3：音轨元数据（**不含** CDN 签名 URL）
  .asr/                仅 L3 且加 `--keep-audio`：下载的音频（默认转写完即删）
```

## meta.json 关键字段

| 字段 | 说明 |
|---|---|
| `bvid` / `aid` | 稿件标识 |
| `title` / `desc` | 标题与简介 |
| `duration` | 总时长（秒） |
| `owner_name` / `owner_mid` | UP 主 |
| `stat` | 播放/弹幕/评论/点赞/投币/收藏 |
| `page_count` / `processed_pages` | 分 P 总数与本次处理的分 P |
| `level` | 单一级别，或 `mixed`（各分 P 不一致） |
| `subtitle_is_ai` | 是否全部为 AI 字幕 |
| `asr_enabled` / `asr_used` | 本次是否允许 / 实际使用了本地 ASR |
| `asr_replaced_subtitle` | 是否有分 P 的平台字幕被本地转写替换 |
| `pages[]` | 每个分 P 的明细，见下 |
| `generated_at` / `tool_version` | 生成时间与工具版本 |

`pages[]` 每项：

| 字段 | 说明 |
|---|---|
| `cid` / `page` / `part` | 分 P 标识与标题 |
| `level` | `official_ai_summary` / `subtitle` / `local_asr` / `none` |
| `cue_count` | 字幕条数 |
| `coverage` | **时长覆盖率** = 最后一条字幕结束时间 ÷ 时长。明显低于 1 说明内容可能被截断 |
| `unstable` | **两次独立读取结果不一致**（L3 时表示音频不完整或覆盖率不足） |
| `relevance` | `{matched, total, missing_keywords, low_relevance}` —— 内容与标题的内容词重合情况 |
| `subtitle_lan` / `subtitle_is_ai` | 字幕语言与是否 AI 生成 |
| `asr` | L3 元数据：`info`（模型/设备/精度/耗时/音频时长）+ `audio`（音轨、字节数） |
| `asr_replaced_subtitle` | 该分 P 的平台字幕不可信，已被本地转写替换 |
| `warnings` | 告警（重试、疑似截断、读取不一致、内容错配等），**必须读** |
| `fallback_reasons` | 为什么降级（例如 L1 未登录、L2 字幕未过校验改用 L3） |

## 命中级别

| 级别 | 含义 | 你能直接用的东西 |
|---|---|---|
| `official_ai_summary` | B 站官方 AI 总结 | 整段摘要 + 分段提纲（带时间戳）+ AI 字幕（带起止时间戳） |
| `subtitle` | 平台字幕（人工 CC 或 AI 生成） | 转录文本，需要你自己总结 |
| `local_asr` | **本机** ASR 转写（可选组件，需装 faster-whisper） | 转录文本，需要你自己总结；注意同音字与断句误差 |
| `none` | 无可用内容 | 只有标题/简介 |

> `official_ai_summary` 里的摘要是 **B 站生成的**。采用它时要在回答里说明来源，不要表述成你自己总结的成果。
> `local_asr` 的内容是**本工具在本机生成的**，与平台字幕不是一回事，两者不可互相冒充。

## 字幕选择顺序

L2 取字幕时按以下优先级挑轨（同一语言下人工字幕优先于 AI 字幕）：

1. `zh-Hans` / `zh-CN`（人工）
2. `zh-Hant` / `zh-TW`
3. 其它 `zh*` 或 `ai-zh`
4. 其它 `ai-*`
5. `en*` → 任意

## 三重校验（为什么 L2 需要它们）

实测发现上游字幕接口有三种不同的失败模式，**需要三个独立判据才能覆盖**：

| 失败模式 | 实测表现 | 挡它的判据 |
|---|---|---|
| 内容被截断（「假残缺」） | 首次 6 条，单独重请求 373 条 | **时长覆盖率** ≥ 90% |
| 每次请求返回不同内容 | 同一 cid 连拉三次：155 / 428 / 无字幕轨 | **双读一致性**（每轮独立读两次，内容指纹必须相同） |
| 每次都错、但错得一致（串号） | coverage 100%、双读也一致，内容却完全是另一个视频 | **标题相关性**（内容词零命中即标记） |

第三种的实例：视频《我记得课本里的新疆，不是这样的啊？？》
- L1（`conclusion/get`）拿到「新疆竟然有海……沙漠……农业世界」→ **正确**
- L2（`player/v2`）拿到「大老师前面视频……巫师……上帝视角……顶层设计者」→ **另一个视频**

**L1 与 L2 的信任度不同**：L1 的摘要/提纲/字幕由 B 站关联，实测与标题一致；
L2 需要三重校验全过才可信，任一不过则标记 `unstable` / `low_relevance`。

> 相关性判据的证据基础：目前只在**一个真实错配案例**上验证过，属于启发式提醒，
> 不自动丢弃内容 —— 误报只是让 agent 多看一眼，漏报则会让总结建立在错误素材上。

## 「假残缺」防护

批量或高频抓取时，B 站会返回**内容被截断**的字幕（实测有 6 条 vs 单独重请求 373 条的案例）。
工具的处理方式：

- 用 `coverage`（时长覆盖率）判定是否疑似截断，阈值 90%；
- 不达标则**重新请求 `player/v2` 拿新的 `subtitle_url`**（`auth_key` 有时效）再下载；
- 最多 4 轮，间隔递增（6s + 3s×轮次）；每轮独立读两次做一致性校验；
- 择优保留**覆盖率最高**的一轮（覆盖率比条数更能反映内容是否完整）；
- 全部轮次都不达标时，标记 `unstable` 并在 `index.md` 顶部给出醒目警告。

读产物时若看到截断或错配告警，应在回答里如实提示用户，**不要假装完整**。
